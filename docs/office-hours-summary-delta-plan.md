## Problem Statement

UI의 **시안성**을 높이고, 실사용자가 “해석”이 아니라 “결정”을 바로 할 수 있게 **유익한 요약 + 기준 대비 Δ(차이)** 를 첫 화면에 고정한다.

## What Makes This Cool

- **요약이 맨 위**에 있어서, 결과를 읽는 게 아니라 **결정을 내리게** 한다.
- **기본 합금 DB를 기준으로 Δ(차이)** 를 보여줘서 “수치의 의미”를 즉시 만든다.

## Constraints

- 기준점은 **기본 합금 DB 데이터**로 잡는다.
- MVP(Approach A)에서는 기준 합금을 **1개로 고정**한다.
  - Baseline: `Sn1Ag25Bi0.7Cu`
  - Ground truth solidus: **137.81°C** (표시/비교 기준)
- Δ는 ‘유저가 보기 쉬운 비교’가 목적이므로, **표기 규칙을 고정**한다.
  - 온도 반올림: **0.1°C**
  - 부호: `+0.2°C / -0.2°C / 0.0°C`
- **해석 과대 방지**: baseline과 조성 차이가 클수록 Δ 해석은 참고용이며, 고정 가드레일 문구를 넣는다.

## Premises

1. 사용자에게 제일 중요한 건 “값 자체”보다 **기준 대비 변화(Δ)** 다.
2. 기본 합금 DB는 사용자에게 납득 가능한 기준선이다(이름이 있고, 실측 기반 값이 있다).
3. 상단 요약이 있으면, 결과 패널을 스크롤/탭으로 찾아다니는 시간이 줄어든다.

## Landscape Notes (general)

- 요약이 먼저, 비교/디테일이 아래로 내려오는 ‘inverted pyramid’는 대시보드 UX의 정석이다.
- “숫자만 잔뜩”은 대부분 **baseline/target/Δ 부족**에서 온다.

## Approaches Considered

### Approach A: Minimal viable (selected)

- Summary: 상단에 “절대값 2 + Δ 1” 요약 3개를 고정하고, 아래는 기존 결과 섹션을 유지한다.
- Effort: S
- Risk: Low
- Reuses:
  - `frontend/src/App.jsx` 결과 패널/섹션 접기 패턴
  - `solder_db.py`의 `SOLDER_DB` 엔트리(예: `Sn1Ag25Bi0.7Cu`)
  - `DESIGN.md`의 토큰/레이아웃 원칙(앱 UI, 좌 입력 우 결과, 다크 토큰)

### Approach B: Ideal

- A + 기준 합금(=DB 엔트리) 고정 표시 + 비교 테이블(절대값/Δ/색상) + 경고 플래그

### Approach C: Creative

- B + 규칙 기반 ‘한줄 인사이트/권장 액션’ + 공유 가능한 비교 스냅샷

## Recommended Approach

**Approach A.**  
목표는 “기능 추가”가 아니라 “한눈에 판단”이다. 그래서 요약과 Δ만으로 먼저 이득을 만든다.

## Information Architecture (single screen)

```
Header
  -> Input panel (composition)
  -> Primary action: Analyze

Result area
  -> Summary strip (3 items, always visible)
  -> Guardrail line (always visible)
  -> Details (accordion / existing sections, mostly collapsed)
```

- Summary strip 목적: “기준 대비 좋아졌나/나빠졌나”를 5초 내 판단.
- Details 목적: 근거/세부값은 필요할 때만.

## Data Flow (MVP)

```
INPUT(comp) -> analyze() -> result(solidus, liquidus, range, ...)
                    |
                    +-> baseline(DB: Sn1Ag25Bi0.7Cu, solidus pinned 137.81)

Δsolidus = solidus(result) - solidus(baseline)
Δliquidus = liquidus(result) - liquidus(baseline)
Δrange   = range(result)   - range(baseline)

UI: Summary strip(absolute 2 + delta 1) -> details sections (collapsed)
```

## UI Spec (MVP)

### Summary strip (항상 3칸)

1. **Solidus**
   - 표시: `Solidus 138.0°C`
2. **Baseline**
   - 표시: `vs Sn1Ag25Bi0.7Cu (S=137.81°C)`
3. **Δ 핵심 1개**
   - MVP는 `ΔSolidus`로 고정
   - 표시: `ΔSolidus +0.2°C` / `ΔSolidus -0.2°C` / `ΔSolidus 0.0°C`

### Δ color rules (보조, 텍스트가 주)

- `+`는 상승, `-`는 하락, `0.0`은 동일.
- 색은 보조 신호로만 사용하고, 의미는 **부호 텍스트**로 확정한다.

### Guardrail (고정 문구, MVP 포함)

`baseline은 DB 실측 기반입니다. 조성 차이가 클수록 Δ 해석은 참고용입니다.`

## Interaction states

```
FEATURE        | LOADING                     | EMPTY/NO DATA                         | ERROR                                 | SUCCESS
Summary strip  | 스켈레톤 3칸 + "계산중"     | baseline 미존재 안내 + baseline 고정  | "계산 실패" + 짧은 원인 + 재시도     | 값/Δ 표시
Details        | 섹션 헤더만 표시            | "근거 없음" 상태                      | 섹션 단위 오류 표시                  | 접힌 상태 기본
```

## Responsive

- Desktop: Summary strip 3 columns.
- Mobile: Summary strip 1 column(세로 스택), 라벨 위, 값 아래.

## A11y minimum

- Δ는 색만으로 의미 전달 금지, 부호/텍스트 포함.
- 터치 타깃 44px.
- 아코디언 토글은 키보드(Enter/Space)로 가능.

## Success Criteria

- 결과를 처음 보는 사용자가 5초 내에 “기준 대비 좋아졌나/나빠졌나”를 말할 수 있다.
- 비교를 위해 스크롤로 헤매는 시간이 체감상 줄어든다.
